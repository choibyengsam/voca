# 중국 생사 확인 앱 시장 리서치 및 프로토타입 기획서

## 1. 시장 개요

### 1.1 배경
중국에서 1인 가구가 급증하면서 독거인의 안전 확인에 대한 수요가 폭발적으로 증가하고 있습니다.

#### 주요 통계
| 지표 | 수치 | 출처 |
|------|------|------|
| 2030년 예상 1인 가구 | 최대 2억 명 | 베이커연구원 |
| 60세 이상 노인 인구 (2023) | 2.97억 명 (21.1%) | 국가통계국 |
| 독거 노인 비율 | 54% (약 1.6억 명) | 패각연구원 |
| 2035년 예상 60세+ 인구 | 4억 명 (30%+) | 국가위생건강위원회 |

### 1.2 시장 규모
- **양로 로봇 시장**: 2024년 79억 위안 → 2029년 159억 위안 (연 15% 성장)
- **스마트 양로 시장**: 급속 성장 중

### 2.1 死了么 (Demumu) - 대표 사례

#### 기본 정보
| 항목 | 내용 |
|------|------|
| 출시일 | 2025년 6월 10일 |
| 가격 | 8위안 (약 1,500원) |
| 개발 기간 | 약 1개월 |
| 개발 비용 | 약 1,000위안 (약 20만원) |
| 개발팀 | 95후 3명 (허난성) |
| 순위 | 2026년 1월 iOS 유료앱 1위 |

#### 핵심 기능
1. **체크인 시스템**: 매일 앱 내 버튼을 눌러 생존 확인
2. **자동 알림**: 2일간 미체크인시 긴급연락처에 이메일 발송
3. **간편한 사용**: 회원가입 불필요, 이름과 긴급연락처만 입력
4. **프라이버시 보호**: 위치정보 미수집, 암호화 기술 적용

#### 기술적 특징
```
[핵심 기능 플로우]
사용자 체크인 → 시간 임계값 기반 실종 판단 → 알림 트리거

[기술 스택]
- 프론트엔드: iOS Native (Swift)
- 백엔드: Supabase (클라우드 호스팅)
- 인증: 익명 인증 + 기기 고유 식별자
- 알림: SMTP 이메일 서비스 (단문 미지원)
```

#### 한계점
- 단문(SMS) 미지원 (운영자 심사 필요)
- 기능이 단순해 "데모 수준"이라는 평가
- 고령자 친화성 부족

### 3.2 핵심 기능 구현 로직

#### A. 체크인 시스템
```typescript
// 체크인 이벤트 기록
interface CheckIn {
  id: string;
  device_id: string;
  timestamp: Date;
  location?: GeoLocation;  // 선택적
}

// 체크인 처리
async function handleCheckIn(deviceId: string): Promise<void> {
  await db.checkIns.insert({
    device_id: deviceId,
    timestamp: new Date()
  });

  // 다음 알림 스케줄 갱신
  await scheduler.reschedule(deviceId);
}
```

#### B. 실종 판단 로직
```typescript
// 스케줄러 - 매시간 실행
async function checkMissingUsers(): Promise<void> {
  const threshold = new Date(Date.now() - 48 * 60 * 60 * 1000); // 48시간

  const missingUsers = await db.users.query({
    lastCheckIn: { $lt: threshold },
    notified: false
  });

  for (const user of missingUsers) {
    await sendEmergencyNotification(user);
    await db.users.update(user.id, { notified: true });
  }
}
```

#### C. 알림 시스템
```typescript
// 긴급 연락처 알림
async function sendEmergencyNotification(user: User): Promise<void> {
  const message = `
    [긴급 알림]
    ${user.name}님이 ${daysSinceLastCheckIn}일 동안
    앱에 체크인하지 않았습니다.
    안부를 확인해 주세요.
  `;

  // 이메일 발송
  await emailService.send({
    to: user.emergencyContact.email,
    subject: '긴급: 안부 확인 요청',
    body: message
  });

  // SMS 발송 (선택적)
  if (user.emergencyContact.phone) {
    await smsService.send({
      to: user.emergencyContact.phone,
      message: message
    });
  }
}
```

### 3.3 데이터 모델

```sql
-- 사용자 테이블
CREATE TABLE users (
  id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
  device_id VARCHAR(255) UNIQUE NOT NULL,
  name VARCHAR(100) NOT NULL,
  created_at TIMESTAMP DEFAULT NOW()
);

-- 긴급 연락처 테이블
CREATE TABLE emergency_contacts (
  id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
  user_id UUID REFERENCES users(id),
  name VARCHAR(100) NOT NULL,
  email VARCHAR(255),
  phone VARCHAR(20),
  relationship VARCHAR(50)
);

-- 체크인 기록 테이블
CREATE TABLE check_ins (
  id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
  user_id UUID REFERENCES users(id),
  timestamp TIMESTAMP DEFAULT NOW(),
  method VARCHAR(20) DEFAULT 'manual'  -- manual, auto, voice
);

-- 알림 기록 테이블
CREATE TABLE notifications (
  id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
  user_id UUID REFERENCES users(id),
  contact_id UUID REFERENCES emergency_contacts(id),
  sent_at TIMESTAMP DEFAULT NOW(),
  type VARCHAR(20),  -- email, sms, push
  status VARCHAR(20)  -- sent, delivered, failed
);
```

## 4. 프로토타입 기획

### 4.1 제품 개요

| 항목 | 내용 |
|------|------|
| 제품명 | 안심지킴이 (SafeGuard) |
| 타겟 | 독거노인 및 1인 가구 (20-80세) |
| 플랫폼 | iOS, Android, Web |
| 핵심 가치 | 간편함, 신뢰성, 프라이버시 보호 |

### 4.2 사용자 페르소나

#### 페르소나 1: 독거 노인
- **이름**: 김순자 (75세)
- **상황**: 자녀가 해외 거주, 혼자 사는 노인
- **니즈**: 복잡하지 않은 조작, 자녀에게 안심 제공
- **기술 수준**: 스마트폰 기본 사용 가능

#### 페르소나 2: 도시 1인 가구
- **이름**: 이민수 (32세)
- **상황**: 서울에서 혼자 사는 직장인
- **니즈**: 만약의 상황 대비, 부모님 안심
- **기술 수준**: 높음

## 5. 경쟁 분석 및 차별화 전략

### 5.1 SWOT 분석

| | 긍정적 | 부정적 |
|---|---|---|
| **내부** | **강점 (Strengths)** | **약점 (Weaknesses)** |
| | - 간단한 UX | - 수익 모델 불확실 |
| | - 저비용 개발 가능 | - 기술 진입장벽 낮음 |
| | - 시장 니즈 명확 | - 법적 이슈 가능성 |
| **외부** | **기회 (Opportunities)** | **위협 (Threats)** |
| | - 고령화 사회 가속화 | - 대기업 진입 가능성 |
| | - 1인 가구 급증 | - 유사 앱 난립 |
| | - 정부 지원 가능 | - 개인정보 규제 |

### 5.2 차별화 포인트

1. **시니어 친화 UX**: 큰 글씨, 음성 기능, 단순한 인터페이스
2. **프라이버시 우선**: 최소 정보 수집, 위치 추적 옵션화
3. **다중 알림 채널**: 이메일 + SMS + 카카오톡 연동
4. **가족 연결**: 보호자용 대시보드로 양방향 안심
5. **정부/기업 협력**: B2G/B2B 확장성

## 6. 리스크 및 고려사항

### 6.1 법적 고려사항
- 개인정보 보호법 준수 (GDPR, 중국 개인정보보호법)
- 긴급 알림 오작동 시 책임 소재
- 건강/의료 관련 규제

### 6.2 기술적 리스크
- 알림 시스템 장애 시 대응 방안 필요
- 오탐지 (False Positive) 최소화
- 배터리 최적화

### 6.3 윤리적 고려
- 앱 이름/톤 (생사 확인이라는 직접적 표현 지양)
- 고독사 문제의 근본적 해결은 아님
- 기술 의존성 vs 인간적 돌봄의 균형
